# 用户侧订单中心筛选与历史订单可找回性补强

## Goal

让用户侧订单入口从“最近购买列表”升级为可操作的订单中心：买家可以按订单生命周期筛选已加载订单、快速定位当前页订单、理解未知状态和深链失败，并在支付、取消、发货、详情刷新后看到列表筛选即时迁移。

## Scope

- 前端商城页订单中心体验增强。
- 复用现有订单详情刷新和列表合并逻辑。
- 不新增后端跨页搜索 API，不伪造后端查询能力。
- 不扩展售后、退款、订单后端状态机。

## Requirements

- 增加订单状态分段筛选：全部、待支付、待发货、已发货、已取消、未识别。
- 筛选分类必须由 `mallOrderStatusModel` 推导，Vue template 不重复写状态判断。
- unknown 状态保留原始状态值，并在“未识别”筛选和全部列表中有清晰展示。
- 支持按 `orderNo` 或 `orderId` 在已加载订单中快速定位并选中。
- 当前已加载列表未命中时，提示用户可以翻页继续查找或从订单链接恢复详情。
- 选中订单详情后，列表卡片保持高亮并展示最后更新时间。
- 详情刷新、支付成功、取消、发货等已有路径继续复用列表合并逻辑，并让当前筛选结果即时反映状态迁移。
- `/mall?orderId=...` 无权限、不存在或无效时，不清空最近购买列表，订单中心展示最近购买建议。
- URL 带无效 `orderId` 时必须区别于普通空态，并提供一键清除订单链接参数、返回最近购买的操作。

## Acceptance Criteria

- [ ] 订单列表可按全部、待支付、待发货、已发货、已取消、未识别筛选。
- [ ] 筛选分类和未知状态展示由模型层方法覆盖。
- [ ] 当前页搜索命中 `orderNo` 或 `orderId` 时选中并高亮对应卡片。
- [ ] 当前页搜索无结果时，不误导为后端全量无结果，并展示翻页/链接恢复提示。
- [ ] 详情刷新后，当前筛选列表能随状态迁移更新。
- [ ] 深链失败时，最近购买列表保留，且展示专用恢复提示和清除链接参数操作。
- [ ] 纯模型测试覆盖筛选分类、unknown 原始状态展示、刷新后筛选迁移、搜索命中/无结果、深链失败不清空最近购买列表。

## Technical Notes

- 优先修改 `frontend/src/views/mall/mallOrderStatusModel.ts` 和 `frontend/src/views/mall/MallStorefrontView.vue`。
- 如已有 composable 管理订单详情刷新或列表合并，应复用，不拆出新抽象，除非能减少实际重复。
- API 能力边界保持前端文案明确：搜索只针对已加载订单，跨页精确搜索另行定义后端 `listOrders` 查询契约。
- 当前任务不更新后端 spec，不改数据库，不改网关 API。

## Implementation Plan

1. 读取前端相关 spec 与共享 guide，确认组件、状态、类型、API 边界和质量要求。
2. 研究商城订单页、订单状态模型、已有列表合并和测试文件。
3. 在状态模型中增加订单筛选分类、筛选选项、列表搜索/定位、深链失败展示模型。
4. 在商城页订单中心加入分段筛选、搜索输入、命中选中、高亮和深链恢复操作。
5. 补充 Vitest 模型测试和必要的组件逻辑测试，优先覆盖纯函数。
6. 执行 `$check` 的 diff/spec/lint/typecheck 流程，修复发现的问题。
7. 执行 `$finish-work` 检查，输出测试命令和 git 同步命令。
