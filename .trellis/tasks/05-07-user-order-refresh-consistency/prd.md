# 用户侧订单状态刷新与一致性反馈补强

## Goal

补强用户侧订单详情、最近购买列表、支付刷新和深链恢复的状态一致性反馈，让买家知道当前展示是否最新、哪些状态来自订单快照、哪些状态来自支付刷新，以及刷新失败时当前订单详情仍被保留。

## Requirements

- 订单详情展示订单最后更新时间 `updatedAt`。
- 订单详情刷新按钮旁说明刷新会更新订单状态和物流信息。
- 订单详情刷新成功后给出轻量成功反馈，刷新失败时保留当前订单详情并展示 `code`、`message`、`traceId`。
- 订单详情刷新后同步合并最近购买列表中对应订单卡片。
- 支付成功后同步最近购买列表阶段标识。
- 管理端发货后，用户刷新详情时最近购买列表同步为已发货。
- `unknown` 或未识别状态继续显示原始值，不导致 UI 崩溃。
- 有 `paymentNo` 时允许刷新支付状态。
- 没有 `paymentNo` 且订单为 `paid` 时，说明支付状态来自订单快照。
- 已取消或已发货订单禁用支付刷新时展示明确原因。
- 支付刷新失败时保留当前订单状态，不覆盖为 `unknown`。
- `/mall?orderId=...` 深链加载时区分“正在恢复订单详情”和普通空态。
- `paymentNo` 缺失时不伪造支付单。
- 订单不存在或无权限时展示可理解错误，并建议返回最近购买。
- 移动端下刷新提示、更新时间、错误 `traceId`、状态 chips 和列表卡片操作区不互相挤压或重叠。

## Acceptance Criteria

- [ ] 订单详情展示最后更新时间，并提供刷新状态和物流信息的清晰提示。
- [ ] 详情刷新成功会更新详情和最近购买列表中的同一订单。
- [ ] 详情刷新失败保留原订单详情，并展示后端错误信息。
- [ ] 支付刷新区域能说明支付状态来源和禁用原因。
- [ ] 深链恢复订单详情时有专用 loading/error 文案。
- [ ] 无 `paymentNo` 的 paid 订单不会创建虚假支付单。
- [ ] 390px 宽度下详情顶部 chips、刷新区和错误 traceId 可换行显示。
- [ ] 单元测试覆盖列表合并、支付来源说明、刷新失败保留、unknown 状态和支付刷新禁用原因。

## Technical Notes

- 本任务主要是前端闭环，不新增或修改后端 API 契约。
- 优先复用 `mallOrderStatusModel` 现有订单生命周期、物流和操作边界推导。
- 如果新增纯模型逻辑，优先测试模型函数，避免把业务规则散落在 Vue template 中。
- 不改变现有 Result envelope 或 Gateway 调用模式；错误展示沿用当前 API 错误提取方式。
