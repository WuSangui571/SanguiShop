# 用户侧订单物流展示补强

## Goal

让买家在用户侧订单体验中清楚看到管理端发货后的履约结果，补齐“管理端发货 -> 用户侧可见”的产品闭环。

## Scope

- 前端用户侧订单详情物流展示。
- 前端用户侧订单列表状态摘要。
- 订单支付后到发货阶段的状态文案打磨。
- 移动端订单卡片与订单结果面板窄屏显示检查。
- 相关订单状态模型或 hook 单元测试补强。

## Requirements

- 订单详情展示履约状态：待发货、已发货、未知状态 fallback。
- 已发货时展示承运商、物流单号、发货时间。
- 未发货时展示明确占位文案，避免用户误以为物流数据缺失。
- 订单列表摘要支持 created、paid、cancelled、shipped 和 unknown fallback。
- `paid + unshipped` 显示为“待发货”。
- `shipped` 显示为“已发货”，并引导用户查看物流单号。
- 不调用真实物流 API，不做物流轨迹查询。
- 窄屏下长物流单号、承运商、发货时间可正常换行，不挤压主要操作。

## Acceptance Criteria

- [ ] 用户侧订单详情能区分待发货、已发货、未知履约状态。
- [ ] 已发货订单详情展示承运商、物流单号、发货时间。
- [ ] 未发货订单详情展示清晰占位文案。
- [ ] 用户侧订单列表状态摘要能覆盖 created、paid、cancelled、shipped、unknown。
- [ ] 相关模型或 composable 测试覆盖无物流信息、待发货、已发货、未知履约状态。
- [ ] lint、typecheck、相关测试通过，或记录无法运行的原因。

## Technical Notes

- 优先复用现有订单 DTO 字段，不扩后端 API 契约。
- 优先在订单状态模型中集中处理文案，避免 Vue 模板中散落状态判断。
- 不引入新状态管理库或新接口层抽象。
