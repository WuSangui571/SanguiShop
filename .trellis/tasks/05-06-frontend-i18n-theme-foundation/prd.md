# 前端国际化与主题切换基础

## Goal

为 SanguiShop 前端建立全局国际化和明暗主题基础能力，趁当前页面数量较少时统一入口、状态、文案资源和样式变量，后续新增功能默认接入同一套语言和主题切换机制。

## Requirements

- 语言支持简体中文、繁体中文、英文。
- 默认初始语言为简体中文。
- 提供全局语言切换按钮或选择控件，切换后当前页面即时生效。
- 语言偏好持久化到浏览器本地存储，刷新页面后保持。
- 提供全局浅色/深色主题切换按钮，切换后当前页面即时生效。
- 主题偏好持久化到浏览器本地存储，刷新页面后保持。
- 默认主题为浅色模式。
- 页面错误、请求错误、表单错误和 traceId 展示必须使用 UTF-8 正常中文，不引入乱码文本。
- 当前主要业务页面的用户可见文案尽量接入国际化，包括商城登录、商城首页、商品详情/购物车/结算、运维登录、权限页、补偿运维看板。
- 品牌名、logo 文字、固定业务标识和后端返回的商品名/订单号/错误 code 可保持原样。
- 后续开发应有清晰的翻译键、语言类型、主题状态和 CSS 变量模式可复用。

## Acceptance Criteria

- [ ] 首次打开前端默认显示简体中文和浅色主题。
- [ ] 用户可一键切换到繁体中文或英文，刷新后仍保持所选语言。
- [ ] 用户可一键切换浅色/深色主题，刷新后仍保持所选主题。
- [ ] `document.documentElement` 或等效全局节点带有当前语言和主题标识，CSS 可全局响应。
- [ ] 当前主要页面不再依赖散落的硬编码 UI 文案作为默认开发方式。
- [ ] 错误展示保留 `code/message/traceId`，且中文文案不乱码。
- [ ] TypeScript 类型检查通过。
- [ ] 前端 lint/build 通过。
- [ ] 新增或更新测试覆盖语言/主题默认值、持久化和切换行为。
- [ ] frontend spec 记录后续页面接入 i18n/theme 的约定。

## Technical Notes

- 当前任务只修改 `frontend/` 和必要的 `.trellis/spec/frontend/` 文档。
- 不引入重量级状态管理，优先使用 Vue 3 composable + provide/inject 或轻量模块状态，除非现有项目已经有 Pinia。
- 不改后端 API，不翻译后端返回的业务数据；前端只翻译自己的 UI 文案和兜底错误提示。
- 翻译资源必须保存为 UTF-8，并避免复制已有乱码内容。
- CSS 主题优先通过语义变量实现，避免后续页面写死颜色。

## Plan

1. 读取 frontend 相关 spec：目录结构、组件、hooks、状态管理、类型安全、API 合约、质量指南，以及 shared guides。
2. 调研当前 `frontend/src` 的入口、页面、composable、样式和测试模式。
3. 新增全局 app preferences/i18n/theme 模块，定义语言类型、主题类型、翻译字典、持久化 key 和切换 API。
4. 在 `main.ts`/`App.vue` 接入全局 provider 和顶部切换控件。
5. 将当前主要页面文案迁移到翻译键，保留品牌/业务标识。
6. 改造 `styles.css` 为浅色/深色 CSS 变量，并修复页面颜色对比。
7. 增加测试覆盖默认值、localStorage 持久化、语言/主题切换。
8. 执行 `$check`：按 changed files 读取质量 spec，跑 lint/typecheck/build/tests，修复发现的问题。
9. 执行 `$finish-work`：给出测试命令和 git 同步命令。
