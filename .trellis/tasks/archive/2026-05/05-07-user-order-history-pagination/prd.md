# 用户侧订单详情入口与订单历史分页体验补强

## Goal

把用户侧订单中心从“当前页筛选与找回”推进到“分页历史可浏览、深链可恢复、列表行为可预期”，在不新增后端搜索能力、不扩展退款/售后契约的前提下，补强订单分页、当前页搜索、详情入口、空态与错误态。

## Scope

- 前端商城用户订单区域。
- 订单列表分页信息、翻页交互、当前筛选与搜索提示。
- 当前页搜索未命中后的上一页/下一页继续查找提示。
- 订单详情入口、URL 参数、选中高亮、详情刷新状态与深链恢复。
- 普通无订单、筛选无结果、搜索未命中、深链失败的空态文案。
- 模型与组件相关测试。

## Non-Goals

- 不新增后端全量订单搜索 API。
- 不声称当前页搜索代表全量无结果。
- 不改订单、支付、退款、售后状态机。
- 不新增数据库字段、MQ、Redis 或网关契约。
- 不改管理端订单能力。

## Requirements

- 订单分页区域明确展示当前页、总数、每页数量，并提供可预期的上一页/下一页能力。
- 翻页后保留当前筛选状态；搜索提示必须明确限定在当前页或已加载上下文内。
- 当前筛选无结果时区分“当前页无匹配”和“没有订单”。
- 当前页搜索未命中时提供“上一页继续查找 / 下一页继续查找”的轻量操作，不能暗示后端全量无结果。
- 纯数字查询继续保持 `orderId` 精确优先，`orderNo` 模糊次之。
- 从列表进入详情后，URL 参数、选中高亮、详情刷新状态保持一致。
- 深链恢复成功但当前页列表没有该订单时，应合并进当前列表或显示“来自订单链接”的临时详情标签。
- 深链失败后清除参数路径，继续保留最近购买列表。
- 后端错误继续展示 `code/message/traceId`。
- unknown 状态继续进入“未识别”筛选。

## Acceptance Criteria

- [ ] 用户能看到订单分页的页码、总数和每页数量。
- [ ] 翻页不会重置当前筛选。
- [ ] 当前页筛选无结果、没有订单、搜索未命中、深链失败的文案各自不同。
- [ ] 搜索未命中提供可用的上一页/下一页继续查找动作。
- [ ] 数字搜索命中顺序仍为精确 `orderId` 优先，再模糊 `orderNo`。
- [ ] 列表点击详情会同步 URL 参数、选中高亮和详情状态。
- [ ] 深链恢复成功但不在当前页列表中时，详情仍可稳定展示并有来源提示。
- [ ] 清除链接参数后回到最近购买列表。
- [ ] 模型测试覆盖分页搜索提示、筛选加翻页状态、深链临时详情策略和清除链接恢复。

## Technical Notes

- 优先复用现有 `mallOrderStatusModel` 中的订单分类、筛选、搜索和恢复模型。
- 保持 API 请求通过既有前端订单服务，不新增后端接口。
- 分页状态若已有后端响应字段则读取现有契约；若当前前端仅有已加载列表，则 UI 文案必须明确“当前页/已加载”边界。
- 测试优先放在模型层，必要时补充组件行为测试。
